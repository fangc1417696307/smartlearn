## 1. 项目概述

### 1.1 项目背景
传统在线学习平台依赖繁琐表单收集学生信息，且学习资源千篇一律，难以匹配个体差异。本项目旨在打造一套**个性化资源生成与学习多智能体系统**：通过自然语言对话构建学生画像，由多智能体协同生成个性化多模态学习资源，并规划个性化学习路径、实现精准推送，最终形成"画像 → 生成 → 路径 → 推送 → 答疑 → 评估"的完整学习闭环。

### 1.2 项目目标
1. **对学习者**：把"自己到处找资料"变成"对话生成贴合自己的资料"，提升学习的针对性与效率。
2. **对系统**：通过「动态画像 + 多智能体」实现资源生成与推送的千人千面。
3. **对期末验收**：让「多智能体架构、多模态生成、动态画像」三大技术点看得见、讲得清。

### 1.3 项目定位
- 功能从简，聚焦完整闭环与核心亮点，不追求大而全。
- 学科锁定**计算机类**，便于把代码实操案例、CS 课程讲解做深做精。

| 用户层 | 是谁 | 核心诉求 | 典型场景 |
|---|---|---|---|
| 学习者 | 计算机类专业学生 | 少填表、得到贴合自己的资料与学习路径；知道先学什么后学什么；卡壳时能答疑；能量化掌握情况 | 课程预习/复习、考前突击、攻克薄弱知识点、做题查漏补缺 |

| 演示者 | 开发者本人 | 功能可控、可重复演示、亮点突出、风险可控 | 现场演示、录制演示视频 |

## 3. 产品范围

### 3.1 本期范围

| 优先级 | 功能 | 说明 |
|---|---|---|
| Must（必须） | 对话式学习画像构建 | ≥6 维度、随学随新 |
| Must（必须） | 多智能体资源生成 | 6 种资源全做 |
| Must（必须） | 个性化学习路径规划 + 资源推送 | 路径一次性固定，推送精准化 |
| Should（应该） | 智能辅导（答疑） | 纯文字解答 |
| Should（应该） | 学习效果评估 | 客观题自动判 + 主观题 LLM 判 |

> 注：答疑与评估原为"加分项"，经确认本期**均要做**，故列入 Should。

### 3.2 明确不做（本期）
- 不生成真视频（不调用文本生成视频模型）。
- 不做题目讲解视频。
- 学习路径不做实时动态重排（评估结果只调推送、不改路径）。

## 4. 核心功能需求

### 4.1 用户账号体系

- **功能描述**：多用户系统，支持注册、登录、鉴权、数据隔离。
- **关键规则**：
  - 完整账号体系（注册登录、密码鉴权、找回密码等按标准账号体系实现）。
  - 每个学生拥有独立的画像、学习记录与推送数据，数据相互隔离。
  - 学科范围为计算机类，注册时可采集/选择专业信息。

### 4.2 对话式学习画像构建

- **功能描述**：摒弃传统表单，学生通过自然语言对话，系统自动抽取特征，构建并持续更新动态学生画像。
- **画像维度（6 个，已确认）**：
  1. 知识基础
  2. 认知风格
  3. 易错点偏好
  4. 学习目标
  5. 学习历史
  6. 学习节奏
- **关键规则**：
  - 结合学生的专业、学习目标、学习历史等信息自动抽取特征。
  - 画像"随学随新"，随学习过程动态更新。
- **待确认（TBD）**：
  - 画像更新触发时机（学习/练习后自动更新 vs 学生主动触发）。
  - 首次画像构建所需对话轮次。

### 4.3 多智能体协同的资源生成

- **功能描述**：由不同角色智能体协作，结合学生提供的专业、课程内容、知识短板、学习需求，生成针对性的多模态学习资料。
- **资源类型（6 种，全做）**：
  1. 专业课程讲解文档
  2. 知识点思维导图
  3. 不同类型练习题目
  4. 拓展阅读材料
  5. 代码实操案例
  6. B 站视频推荐（预设链接库）
- **关键规则**：
  - 视频资源不实时生成，从**预设 B 站链接库**中按知识点匹配推荐。
  - 练习题目覆盖不同类型；判分规则见 4.6。
- **待确认（TBD）**：
  - 思维导图输出形式（静态图片 vs 可交互网页）。
  - 生成内容是否支持导出/下载（PDF / 图片 / 代码文件）。

### 4.4 个性化学习路径规划与资源推送

- **路径规划**：
  - 整合系统生成的个性化资源，结合专业、学习进度、知识掌握情况与学习偏好，规划学习步骤与顺序。
  - **路径一次性生成即固定**，后续不因评估结果重排。
- **资源推送**：
  - 基于画像精准推送，涵盖文档、视频（B 站链接）、题库、实操案例等多类型内容。
  - 评估结果可**动态调整推送策略**（但路径本身不变）。
- **进度记录**：
  - 由学生**手动标记**"已完成 / 已掌握"。
- **待确认（TBD）**：
  - 路径生成触发时机（画像构建完成后自动生成 vs 学生点击生成）。
  - 推送时机（主动推送到首页 vs 学生在资源库自行取用）。

### 4.5 智能辅导（答疑，加分项）

- **功能描述**：学生在学习过程中遇到问题时，系统提供即时答疑服务。
- **解答形式**：**纯文字**解答（不做图解、不做视频）。
- **关键规则**：结合智能体数据分析与大模型知识支持，提供针对性学习引导。

### 4.6 学习效果评估（加分项）

- **功能描述**：实时跟踪学习行为、练习测试情况、资源使用反馈，实现多维度精准评估，并根据结果调整资源推送策略。
- **判分机制（已确认）**：
  - 客观题（选择/判断/填空等）系统自动判分。
  - 主观题由 LLM 判分。
- **关键规则**：评估结果用于动态调整**推送策略**，不重排学习路径。

## 5. 多智能体架构设计

### 5.1 实现模式（已确认）
- **混合模式**：大部分角色为"逻辑角色"（同一大模型通过角色设定切换身份），个别环节拆成**真正的独立 Agent**。

### 5.2 角色清单（11 个）

| # | 角色 | 职责 | 类型 |
|---|---|---|---|
| 1 | 学情分析师 | 对话式抽取画像特征 | 逻辑角色 |
| 2 | 课程讲师 | 生成课程讲解文档 | 逻辑角色 |
| 3 | 导图绘制师 | 生成知识点思维导图 | 逻辑角色 |
| 4 | 出题官 | 出练习题 + 判分 | **独立 Agent** |
| 5 | 阅读助手 | 生成拓展阅读材料 | 逻辑角色 |
| 6 | 代码导师 | 生成代码实操案例 | 逻辑角色 |
| 7 | 视频推荐员 | 从 B 站库匹配推荐视频 | 逻辑角色 |
| 8 | 路径规划师 | 规划学习步骤与顺序 | 逻辑角色 |
| 9 | 资源推送员 | 按画像精准推送资源 | 逻辑角色 |
| 10 | 答疑老师 | 纯文字解答问题 | 逻辑角色 |
| 11 | 评估分析师 | 学习效果评估分析 | **独立 Agent** |

### 5.3 协作流程（示意）
1. **学情分析师**与学生对话 → 抽取画像特征（6 维度）。
2. **路径规划师**基于画像 + 资源，一次性生成学习路径。
3. 各资源角色（课程讲师 / 导图绘制师 / 出题官 / 阅读助手 / 代码导师 / 视频推荐员）按路径协作生成 6 种资源。
4. **资源推送员**基于画像推送资源。
5. 学生手动标记进度 → **出题官**判分 → **评估分析师**评估 → 调整推送策略（路径不变）。
6. 学生提问 → **答疑老师**纯文字解答。

## 6. 关键业务决策汇总

| 模块 | 决策 |
|---|---|
| 用户体系 | 多用户 + 完整账号体系（注册登录、鉴权、数据隔离） |
| 学科范围 | 锁定计算机类 |
| 画像维度 | 知识基础 / 认知风格 / 易错点偏好 / 学习目标 / 学习历史 / 学习节奏 |
| 画像构建 | 对话式抽取、随学随新 |
| 多智能体 | 混合模式，11 角色，其中「出题与判分」「学习评估分析」为独立 Agent |
| 资源种类 | 6 种全做（讲解文档 / 思维导图 / 练习题 / 拓展阅读 / 代码实操案例 / B 站视频推荐） |
| 视频 | 不生成真视频，用预设 B 站链接库；题目讲解视频不做 |
| 学习路径 | 一次性生成即固定，评估只调推送、不重排路径 |
| 进度记录 | 学生手动标记"已完成/已掌握" |
| 答疑形式 | 纯文字 |
| 练习判分 | 客观题自动判 + 主观题 LLM 判 |
| 加分项 | 答疑 + 学习效果评估都做 |

## 8. 风险与依赖

| 风险/依赖 | 说明 | 应对 |
|---|---|---|
| 多模态生成范围 | 已明确不做真视频，风险显著降低 | 图解/思维导图输出形式仍需确认 |
| LLM 判分准确性 | 主观题 LLM 判分存在误判 | 客观题为主，主观题判分结果可提示人工复核 |
| B 站链接库维护 | 预设链接库需持续补充 | 初期人工整理，按知识点分类 |
| 演示稳定性 | 多智能体协作链路长，需可控 | 优先保障主流程（画像→生成→路径→推送）稳定 |
